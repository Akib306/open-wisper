# Swift implementation and verification

Checkpoint: October 31, 2026. Implementation: `native/swift`. This is an independently authored development baseline based on the native plan, not a parity claim about Wispr Flow.

## What the implementation covers

| Contract area | Implemented behavior |
| --- | --- |
| App lifecycle | AppKit status item/menu, compact SwiftUI review/settings, nonactivating recording panel; capture lives outside views. Stable bundle ID `dev.akib.openwisper.swift`, macOS 14 deployment target. |
| Sessions | MainActor coordinator, session IDs, idempotent commands, immediate cancellation of delivery authorization, late-result rejection, automatic stop, cleanup before another session, quit cleanup. |
| Audio | AVAudioEngine tap → preallocated lock-free C11 ring → serial worker → high-quality AVAudioConverter → mono 16 kHz signed-16 WAV. Explicit channel average/clipping, final flush, bounded frames, overflow failure. |
| Device changes | Fail and release capture on default-device/format/alive notifications, engine configuration changes, sleep, permission revocation, or missing frames. No automatic restart or input-device picker. |
| Local ASR | Exact profile and streamed SHA-256 validation, direct argv, explicit environment/cwd, short-lived process group, bounded stdout/stderr, timeout/TERM/KILL and reap, private temporary files. |
| Delivery | Cursor insertion by default; captures the destination at Stop and rechecks process start/PID, bundle, element, role, selection, security and editability. Web content uses one targeted Paste; native fields retain direct AXSelectedText where supported. Clipboard restoration follows a data request or bounded timeout, subject to ownership. Single-use token; no activation, whole-value write, Return, or ambiguous retry. Failed delivery offers a quiet Review/Copy indicator. |
| Storage | Atomic validated versioned settings; no transcript/audio history. Safe recognized stale-directory recovery with ownership/mode/marker/lock checks and no recursive deletion. |
| Hotkeys/permissions | Carbon combinations, repeat-key suppression, registration before release and rollback on save failure; microphone requested only by recording; Cancel/Quit release unanswered permission waits and ignore late responses; Accessibility optional, never prompted on launch. |
| Metrics | Monotonic inference and stop-to-review timing, audio duration, real-time factor, outcome. No app/process-tree memory benchmark is claimed. |

## Pending manual/release checks

Live microphone capture, fresh-install TCC dialogs/denial/revocation, nonactivating indicator behavior across Spaces/fullscreen, physical device unplug/Bluetooth/sleep scenarios, real shortcut conflicts and permission continuity across updates still need controlled packaged validation. Controlled audio tests used generated audio, and delivery tests used private pasteboards without inserting into user documents. The uncontrolled recording incident during live UI validation is recorded above; it does not substitute for a controlled microphone test.

Cross-application delivery is **not release-qualified**: test native fields, plain browser fields, contenteditable, secure fields, focus/selection changes, app exit/PID reuse, delayed Paste consumers, clipboard managers, and ambiguous timeouts in dedicated scratch documents after granting Accessibility to the packaged app. Tests use fake OS boundaries and private pasteboards; they do not prove actual CGEvent delivery or every editor's behavior. The cross-process validation/write race remains, and even AX success is only an insertion request. Clipboard preservation is bounded and conditional; a data request can be from a clipboard manager, and neither it nor the 500 ms grace period verifies editor insertion.

Also pending: macOS 14 hardware/runtime coverage, signed/notarized public distribution, chosen project license, larger original audio corpus, controlled network-egress observation, crash/power-loss recovery trials, external process-tree resource measurement, and comparative Rust/Electron runs. The Rust implementation and P1/P2 features are not part of this checkpoint.
