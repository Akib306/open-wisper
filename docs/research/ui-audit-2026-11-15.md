# Swift UI and UX audit — November 15, 2026

Method: two independent source assessments, followed by native rendering, AppKit interaction tests, implementation, and review. Target: the running Swift app and `native/swift/Sources/OpenWisper/Views.swift`. Operate mode; retain the approved Pebble palette, bottom pill, circular primary action, and native window behavior. Rust and Electron were outside this running-app audit.

The interface feels appropriate for a quiet dictation utility. Its strongest features are intentional recording, a nonactivating indicator, local transcription, and a reliable Review/Copy fallback. The main weakness was the amount of explanatory and decorative text between the user and those actions.

## Findings and fixes

1. **P1 — Setup was a disabled dead end.** Start was disabled when the engine was unavailable and the recovery action appeared elsewhere. The circle now becomes **Set up**, opens Settings, and reports verification explicitly while checking. Missing, checking and failed engine states have synthetic fixtures.
2. **P1 — Long transcripts buried their own actions.** Copy and Dismiss lived after the full transcript in one scroll view. **Copy** and **Clear** now remain outside the scrolling text, above the persistent memory footer. The minimum-size long-transcript render confirms both actions remain visible.
3. **P1 — Transcript clearing was easy to misunderstand.** The established product contract clears the in-memory transcript when the window closes or a new dictation starts. That contract was preserved. Review now states those consequences, and the ambiguous Dismiss action is **Clear**. This improves disclosure; it does not add undo or saved history.
4. **P2 — Decorative copy competed with recording.** Replaced poetic state headings and removed the generic Settings introduction, the unrelated Apple Speech comparison, the repeated privacy badge, repeated memory captions, and always-visible session timing. Ready retains a short cursor instruction and the actual shortcut. Recording explains the difference between in-window Stop and insertion from the editor.
5. **P2 — Engine failure could hide in a disclosure.** Availability is visible beside model selection. Details open when verification fails; profile paths, model verification and custom-profile selection remain available.
6. **P2 — Copy had incomplete feedback.** Copy failure now has a typed outcome separate from insertion failure; the UI no longer identifies errors by matching message text. The pill shows **Copy failed** and **Retry**. Success shows **Copied**, then dismisses after the existing brief feedback interval while preserving the in-memory transcript.
7. **P2 — Pill error labels clipped.** The first render found a truncated copy-error title alongside a duplicate error button. The final pill uses a short state and a verb-labelled retry action, fitting its existing width.
8. **P2 — Settings and keyboard navigation imposed extra work.** Grouped Accessibility status with insertion, kept the clipboard disclosure, moved occasional-use file access into a disclosure, and added Command-1/2/3 for Ready/Review/Settings. Engine selection, all four shortcut modifiers, permissions, recording limits and timeout controls remain present.

No P0 issue was identified. Existing capture, cursor-target validation, guarded Paste, cancellation authorization, privacy defaults and permission setup were preserved.

## Cognitive load and user journey

The baseline had moderate cognitive load: primary-task focus, progressive disclosure, and one-decision-at-a-time guidance were weakened by repeated explanations. The revised Ready surface has one primary action and the actual shortcut. Settings groups model, shortcut and delivery choices; the four shortcut modifiers are one combined configuration decision rather than unrelated top-level choices.

The recording pill remains the strongest moment. Setup and failed delivery are the most stressful moments; both now give a clearer next action. The remaining user-control risk is the intentional, nonrecoverable clearing of the current session. First-time and privacy-conscious users still need the clipboard and lifetime explanations; those were retained rather than cut for visual simplicity. Keyboard users gain direct navigation and retain Copy and cancellation commands.

## Verification and evidence

- **117 tests across 22 suites passed**, including three AppKit keyboard journeys against isolated synthetic sessions. The tests do not record audio, insert into an editor, write personal settings, register a global shortcut, or write the general clipboard.
- Independent final source review found no required changes. The main agent separately verified the build, test results and renders.
- Two bounded native visual rounds: first inspection, one batched correction, final confirmation. Covered light/dark, 340 × 420 minimum, 360 × 480 default and 900 × 720 wide layouts; recording, processing, review, long text, interruption, engine setup/checking/failure, Copy success/failure and cancellation states.
- Ready/Review/Settings navigation, primary setup, and long-transcript Copy tested with AppKit key events. Copy confirmation expiry and transcript preservation have lifecycle coverage.
- Removing Copied from the brief-feedback dismissal condition made the new lifecycle regression fail. Source was restored byte-for-byte and the complete 117-test suite passed. The confirmation test waits for the dismissal transition instead of assuming a 100 ms scheduling margin.
- Main text contrast: 10.78:1 light, 13.69:1 dark. Supporting text: 5.36:1 light, 8.94:1 dark. Primary action text: 7.69:1 light, 7.45:1 dark. Copper recovery text: 4.93:1 light, 6.81:1 dark. Disabled controls are excluded from normal-text contrast claims.
- The installed app was inspected through macOS Accessibility and contained a current transcript. It was not replaced, quit, cleared or re-signed. A separate signed update bundle was staged under `native/swift/dist`.

Staged bundle: `native/swift/dist/Open Wisper Swift UI Update.app`. Its executable SHA-256 is `a80305cf0cfa08b000326923673ac63c01348c419d0603d9d24083a44ca95c98`. Release build, strict recursive code-signature verification, and all three bundled engine/model profile checks passed. This is a locally staged update, not a newly published release or a replacement of `/Applications/Open Wisper Swift.app`.

Verification limits:

- Desktop window capture returned `could not create image from window`. Native render mode supplied the visual evidence instead. Later external AX traversal returned application references in place of window descendants, preventing reliable external pointer-action assertions. Native AppKit keyboard journeys passed; this is not a claim that full external computer-use or VoiceOver testing passed.
- The initial sandboxed suite lacked pasteboard IPC/private-workspace access and was stopped. An unrestricted run exposed an existing cancellation timing test at 1.016 seconds against a one-second bound; it passed unchanged in isolation at 0.111 seconds and in the subsequent combined suite. No worker timeout or existing cancellation threshold was relaxed.
- Web detector, browser overlays, DOM inspection and web breakpoints do not apply to this SwiftUI/AppKit surface. No web server was started. The Impeccable loader's unsupported macOS platform warning was treated as a tooling limitation; product/design schema and skill installation were left alone.
